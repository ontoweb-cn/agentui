### F-01 总览想定总数从 32 跳变为 5

- 现象：总览页最初显示 32 个想定，一段时间后变为 5 个。
- 根因：`DashboardPage` 只请求 `fetchScenarios(10, 0)`；后端先按 `limit` 截断，再排除 `eval_mode` 变体，`limit=10` 最终只剩 5 条。卡片统计又使用了这次截断后的数组长度。
- 修复：总览查询改为 `limit=200`，最近想定列表单独取前 10 条，统计卡片使用完整 `scenarios.length`。
- 验证：后端 `limit=200` 返回 `count=32`，页面总数不再跳变。
- 文件：[DashboardPage.tsx:87](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/pages/DashboardPage.tsx:87)、[DashboardPage.tsx:160](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/pages/DashboardPage.tsx:160)、[DashboardPage.tsx:390](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/pages/DashboardPage.tsx:390)

### F-03 实时事件流 401，启动推演后页面没有实时反馈

## 三、遗留问题

### U-01 完成态刷新后“回合: -”，实时事件流为空

- 现象：推演结束后新开或刷新页面，控制面板显示“回合: -”，实时事件流显示“暂无实时事件”。
- 根因：
  - 当前使用的是 SSE v1，只推送连接建立之后的新事件，不回放历史。
  - `/api/v1/scenarios/{id}/status` 返回完成态时未携带当前回合字段。
  - 刷新后前端 store 被重置，`currentRound` 回到初始值 0。
- 代码位置：[RoundViewPage.tsx:944](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/pages/RoundViewPage.tsx:944)、[store.ts:111](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/store.ts:111)
- 影响：不影响推演执行，但完成态复盘时看不到最后一次实时上下文。
- 建议：接 SSE v2 回放，或在页面初始化时用 `scenario.rounds_completed` / 最近 `round.completed` 事件回填。

### U-02 回合历史表显示 2020 行且所有数值为 `-`

- 现象：控制面板“回合历史 (2020)”页签能打开，但第一列不是 0~5 回合，而是大量空行；红方得分、蓝方得分、红/蓝方认知态势全部显示 `-`。
- 根因：
  - `/api/v1/metrics/{scenario}/history` 当前返回 `records`，内容为逐 Agent 的 `round_history` 原始记录（2020 条）。
  - 前端表格按“每回合 `round` / `red_score` / `blue_score` / `red_cognitive` / `blue_cognitive`”读取，字段与接口不匹配。
- 代码位置：[api.ts:845](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/api.ts:845)、[RoundViewPage.tsx:1383](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/pages/RoundViewPage.tsx:1383)
- 影响：无法从该表查看 6 回合汇总指标。
- 建议：明确该表的指标口径后，由后端补每回合聚合字段，或前端按 `round_num` 聚合，并隐藏当前场景不适用的红/蓝评分列。

### U-03 回合数输入必须始终保留一位数字，清空后重新输入会被串成 `212`

- 实测行为：
  - 初始值 6。
  - 直接设为 3、12 时可以修改。
  - 清空输入后会自动回填为 2。
  - 清空后用键盘依次输入 `1`、`2`，最终值变成 `212`。
- 根因：回合数输入是受控 `number` 输入，每次 `onChange` 都执行 `Math.max(2, Math.floor(value))`；空值或 1 会立刻被改写成 2，光标停在末尾后继续输入就会追加成 `212`。
- 代码位置：[ScenarioListPage.tsx:339](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/pages/ScenarioListPage.tsx:339)、提交时同样钳制：[ScenarioListPage.tsx:213](E:/github/cognitive-wargame/web/agentui/src/features/cognitive-wargame/pages/ScenarioListPage.tsx:213)
- 结论：不是“固定为 6、无法修改”。3、12 都能正常输入；问题是输入过程中必须始终保留一位数字并即时钳制，导致空值和 1 被立即改写，无法自然编辑。
- 建议：
  - 输入框允许保留用户输入的一位数字，不要在每个按键后强制改写成 2。
  - 允许临时空值，失焦或提交时再校验并规范化。
  - 提交时同时校验下限和上限；当前代码只做了 `min=2`，没有在提交时限制 `max=50`。

### U-04 租户 ID 被前端和 BFF 双重限制为 32 位 hex

- 现象：配置 `intellect-enterprise` 后端时，租户 ID 必须是 32 位十六进制字符串，`wargame` 等非 32 位值无法提交。
- 前端校验：[wizard/index.tsx:367](E:/github/agentui/src/pages/wizard/index.tsx:367)、输入框提示与错误态：[wizard/index.tsx:479](E:/github/agentui/src/pages/wizard/index.tsx:479)、[wizard/index.tsx:483](E:/github/agentui/src/pages/wizard/index.tsx:483)
- BFF 校验：[wizard.ts:510](E:/github/agentui/bff/src/routes/wizard.ts:510) 同样要求 32 位 hex，不满足直接返回 400；[wizard.ts:609](E:/github/agentui/bff/src/routes/wizard.ts:609) 还要求该值与 intellect-team `/api/tenant/info` 返回的 `tenant_id` 完全一致。
- 结论：只解除前端 32 位限制不够，BFF 仍会拦截。若产品要求支持 `wargame` 这类非 hex 租户，必须同时改 BFF 校验和 intellect-team 侧契约；否则应保留现状，并在页面提示从 intellect-team 的 `INTELLECT_TENANT_ID` 复制真实值。

### U-05 完成态“实时连接已断开”提示容易误解

- 现象：推演完成后页面显示红色“实时连接已断开”。
- 原因：任务结束后 SSE 连接关闭属于正常行为，但当前 UI 把它当成异常状态展示。
- 建议：完成态改为“推演已结束”或“连接已关闭”，仅在运行中连接失败时显示错误。
