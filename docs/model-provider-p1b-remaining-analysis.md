## 一、P1-b 剩余的三件事 — **已全部实施(2026-11-21,flag 默认关)**

### 1. §4.1 服务令牌强制

模型管理路径(`providers*` / `models*`,**不含** `users/me/models`——身份绑定语义)在三个条件齐备时,强制改用服务账号 `ragAdminToken` 鉴权:

- 路径匹配(`MODEL_MANAGEMENT_PATH_RE`);
- feature flag 开启(见 §4.6);
- 后端配置了 `ragAdminToken`(缺失时自动退回成员令牌,不阻断)。

强制时跳过全部 `X-Intellect-*` 身份头注入(User/Role/Team/Project/Tenant)——服务令牌本身就是身份,混入成员身份头会让 RAG 归属判断混乱。实现上走 `rag-fetch.ts` 既有 `explicit` 分支(调用方显式 Authorization,不覆盖、不重试),**无需改动 `rag-fetch.ts`**。

### 2. §4.4 写权限门控(仅强制服务令牌时生效)

- 模型管理域的非 GET 写操作要求 `admin` / `owner` 角色(与 `llm-auth.ts`、`MemberRole` 既有口径一致);
- **fail-closed**:role 解析失败(TEAM 不可达、令牌无效)一律 403,不允许无法确权者以服务身份改租户配置;60s 角色缓存缓解 TEAM 抖动;
- flag 关闭时门控整体不生效,写请求由上游按成员令牌鉴权,与现状完全一致。

### 3. §4.6 feature flag

`BFF_MODEL_MGMT_SERVICE_TOKEN`,**默认关**。它是行为变更开关而非兼容开关:

- 关(默认)= 本批零行为变化,线上只有已合入的 P1-a"错误可见化"在起作用;
- 回滚 = 置 `false` 即可,无需回代码。

## 二、同源子问题:§4.5 默认模型的 PATCH 归类

flag 开启后 `PATCH /models/default`(设默认模型)命中"非 GET + 模型路径",要求管理员角色——**普通成员设默认模型会得到 403**。**已随 D2 采纳(2026-11-21)确认接受**:默认模型为租户级共享配置,与实例管理同权限级别自洽;业务后续若反馈成员需个人默认,另行立项将默认模型改为用户级数据(见决策简报 §二)。flag 关闭期间无任何影响。
