# 用户手册 — 向导企业版双模式（SSO / 非 SSO）

> 模块:`wizard-ent-sso-mode`  
> 日期:2026-11-23  
> 口径真源:`docs/wizard-enterprise-sso-mode-design.md` v1.2（含 §9 质量/安全）  
> 读者:实施首装的管理员（业务术语，不写实现细节）

---

## 1. 这是什么

首次安装（或管理端「添加后端」进入向导）时，在**选择后端类型**一步会看到两张企业相关卡片，分别对应两种登录方式准备路径：

1. **企业版（SSO模式）** — 用统一认证登录；向导里必须配好公开地址与引导密钥等，完成后按提示写入环境变量并重启服务，登录页才会出现统一认证按钮。  
2. **企业版（非SSO模式）** — 用成员账号密码登录；向导里**不会**出现统一认证配置；以后若要开统一认证，需运维手工改环境变量（本手册不展开）。

两张卡连接的都是同一类「企业后端」，只是首装时是否准备统一认证不同。

社区版 / HERMES / AgentScope 卡片行为不变，不在本手册范围。

---

## 2. 入口

| 场景 | 入口 | 预期 |
|---|---|---|
| 尚未完成首装 | 打开应用会进入向导 | 从欢迎页开始 |
| 已有后端仍要再配 | 管理语境打开 `/wizard?mode=add` | 可进入向导，不被踢回首页 |

步骤条仍为六步：欢迎 → 选择类型 → 连接信息 → 探测 → 确认 → 完成。

---

## 3. 选择类型

### 3.1 卡片顺序与含义

从上到下（或从左到右网格）顺序为：

1. 企业版（SSO模式）  
2. 企业版（非SSO模式）  
3. Intellect Community  
4. HERMES  
5. AgentScope  

未选中任一卡时，「下一步」不可用。

两张企业卡应能**分别选中**（不会点一张却亮两张）。卡片上应能看出「SSO」与「密码」差异（徽章或说明），不能只显示相同的技术类型名让人分不清。

### 3.2 选「企业版（SSO模式）」之后

进入连接信息页后：

- 仍需填写名称、企业后端地址、凭据、企业租户 ID（与以往企业版相同）。  
- **必须出现**统一认证配置区（公开来源地址、引导密钥生成/复制、可选渠道白名单、静默重登等）。  
- **没有**「关闭统一认证 / 跳过」作为主路径；本模式就是要配统一认证。  
- 未填合法公开地址或未生成足够长的引导密钥时，不能进入下一步。

### 3.3 选「企业版（非SSO模式）」之后

- 只需企业连接字段（名称/地址/凭据/租户 ID）。  
- **不出现**统一认证配置区。  
- 可正常探测与完成首装；完成页**不应**要求复制统一认证环境变量（可有「以后可手工开启」类说明，非必须）。

### 3.4 切换卡片

从 SSO 模式改选非 SSO（或反过来）时，统一认证相关填写应清空/重置，避免把上一张卡的配置误带到下一张。

---

## 4. 探测 / 确认 / 完成

| 步骤 | SSO 模式 | 非 SSO 模式 |
|---|---|---|
| 探测 | 检查企业后端可达（租户信息等） | 同左 |
| 确认 | 摘要标明 **「待写入环境变量」**（渠道/公开地址）；**不回显**引导密钥明文；勿写成「已在运行中启用」 | 无统一认证摘要行 |
| 完成 | 展示需写入的环境变量片段（含统一认证相关项）；并提示：**尚未写入环境变量并重启前，登录页不会出现统一认证按钮** | 无统一认证环境变量行 |

说明：向导完成只表示「后端已登记 +（SSO 模式）给出了配置草稿」。统一认证是否真正可用，取决于运维是否按完成页写入环境并重启。

---

## 5. 运维安全注意（粘贴环境变量时）

1. **先看提示再粘贴**：完成页片段是「待写入」草稿，不是系统已生效配置。  
2. **核对每一行**：只应出现预期的 `BFF_SSO_*` / `BFF_PUBLIC_ORIGIN` 等键；若出现异常换行、陌生键名，**不要整段盲贴**，回到向导重新生成或手工编辑。  
3. **公开来源地址**须是用户浏览器实际访问的站点源（含正确 https）；填错会导致回调失败。  
4. **引导密钥**只在向导页面展示一次：复制到密钥保管位置与 `.env`，不要提交到 git，不要要求网关/监控记录完整「创建后端」请求体。  
5. 生产若 BFF 对公网暴露：须按设计 `wizard-enterprise-sso-mode-design.md` §9 完成 SSRF/片段消毒加固，并关闭对不可信来源的私网探测放行。

---

## 6. 登录页关系（首装之后）

- **SSO 模式**且环境已生效：登录页可同时看到**密码框**和**统一认证渠道按钮**（密码保留作运维破窗，不是缺陷）。  
- **非 SSO 模式**（未开统一认证环境）：通常只有密码登录。  
- 统一认证失败时的「联系管理员 / 未开通」等提示，见登录手册；本向导手册不重复。

---

## 7. 错误与边界

| 情况 | 用户可见预期 |
|---|---|
| 未选类型点下一步 | 下一步禁用或无法前进 |
| SSO 模式缺公开地址 / 密钥过短 | 无法进入探测或提交失败并提示原因 |
| 企业租户 ID 格式不对 | 无法前进 / 提交失败（与既有企业版一致） |
| 拉取登录渠道失败 | 可提示服务暂不可用；不阻断「稍后只配地址与密钥」的校验策略以产品实现为准，但密钥与公开地址仍必填 |
| 旧草稿里只有「企业版」无模式区分 | 应重新选择类型，不能静默当成 SSO 模式 |

---

## 8. 明确不做（避免误解）

- 不会在完成页直接「已经登录进统一认证」。  
- 不会把成员令牌塞进浏览器给 HIEDU。  
- 社区版卡片不会出现企业统一认证配置。  
- 「非 SSO 模式」不是永远禁止统一认证，只是本次向导不配；以后改环境变量仍可开启。
